# 여행 동선

여행 일정을 휴대폰에서 보는 정적 웹사이트입니다. GitHub Pages로 배포합니다. 지역과 날짜에 관한 값은 모두 `data/` 안의 파일에 있어서, 데이터만 바꾸면 다른 여행에도 그대로 쓸 수 있습니다. 공유 미리보기와 홈 화면 아이콘은 예외입니다. 바꿀 파일은 [새 여행에 쓰는 법](#새-여행에-쓰는-법)에 정리했습니다.

- 사이트: https://aleph-kim.github.io/travle-plan/
- 현재 데이터: 히로시마 2026년 10월 15일 ~ 19일 ([현재 데이터](#현재-데이터-히로시마-2026))

## 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 전체 (HTML, CSS, JS 한 파일). 화면 문구 사전(한국어, 영어, 일본어) 포함 |
| `data/plan.json` | 여행 설정, 날짜별 일정, 장소, 식당 후보, 저장 장소 |
| `data/weather.json` | 날씨 예보, 날짜 맞바꿈, 비 판정 결과 (GitHub Actions가 생성, 직접 수정하지 않음) |
| `data/i18n.json` | 일정 내용의 영어, 일본어 번역 (한국어 원문이 키) |
| `data/saved/*.csv` | 일정의 바탕이 된 구글 지도 저장 목록 원본 (Google 테이크아웃 CSV: 제목, 메모, URL, 태그, 댓글). 화면에서는 읽지 않음 |
| `config.js` | 구글 Maps Embed API 키 |
| `sw.js` | 오프라인용 서비스 워커 |
| `manifest.webmanifest`, `icon-*.png`, `icon.svg` | 홈 화면 앱(PWA) 설정과 아이콘 |
| `share.png` | 링크 공유 미리보기 이미지 |
| `.github/workflows/weather.yml` | 날씨 갱신 작업 |
| `.github/scripts/weather.py` | Open-Meteo 예보 수집, 날짜 맞바꿈과 비 판정 |

## 데이터 구조

### plan.json

| 키 | 필수 | 내용 |
|---|---|---|
| `trip` | 필수 | 여행 설정 (아래 표) |
| `locations` | 필수 | 날씨를 받을 지점. `{키: {name, lat, lon}}`. 일정의 `weather` 값이 이 키를 가리킴 |
| `rainThreshold` | 필수 | 비 판정 기준 강수 확률(%). 그날 최대 강수 확률이 이 값 이상이면 비 오는 날 |
| `days` | 필수 | 날짜별 일정 |
| `items` | 필수 | 일정 카드 원본. 같은 카드를 여러 일정이 번호로 참조해 파일 크기를 줄임 |
| `flights` | 선택 | 항공편. `label`, `date`, `dep`, `arr`. 없으면 항공편 칸을 숨김 |
| `extras` | 선택 | 일정에 넣지 않은 저장 장소 묶음(구글 지도 저장 목록 등). `{title, items}`. 없으면 "저장 장소 더보기"를 숨김 |
| `onsenPids` | 선택 | 온천 장소 ID 목록. 있으면 날짜 요약에 그날 노천탕 칸을 보여 줌 |
| `onsenTip`, `ratingNote` | 선택 | 화면 맨 아래 안내 문구 (온천 주의사항, 평점 조회 시점). 있는 문구만 표시 |

`trip`

| 키 | 필수 | 내용 | 현재 값 |
|---|---|---|---|
| `title` | 필수 | 문서 제목 | 히로시마 동선 |
| `name`, `period` | 필수 | 화면 상단 제목과 기간 | 히로시마 / 10월 15일 ~ 19일 |
| `timezone` | 필수 | 여행지 시간대. 오늘 탭, 현재 일정, 날씨 날짜, 갱신 종료 판단에 씀 | Asia/Tokyo |
| `currency` | 필수 | 금액 단위 | 엔 |
| `swap` | 선택 | 날씨 맞바꿈 규칙. `base`는 비와 상관없는 일정, `weights`는 날씨가 중요한 일정과 가중치. 없으면 맞바꾸지 않음 | base: city, weights: miyajima 4, onomichi 2 |

`days[]`

- 필수: `date`(YYYY-MM-DD), `label`(탭 이름), `full`(긴 날짜), `default`(기본 일정 키), `plans`
- `plans`: `{일정 키: {...}}`
  - 필수: `title`, `weather`(locations 키), `sun`, `rain`. `sun`과 `rain`은 맑은 날과 비 오는 날 일정의 `items` 번호 목록이고, 비 일정이 따로 없으면 같은 번호를 넣음
  - 선택: `point`(핵심 포인트), `rainPoint`(비 오는 날 핵심 포인트), `rainNote`(비 일정 안내), `towel`(수건 안내)
  - 날짜마다 일정 키를 여러 개 두면 날씨 맞바꿈 후보가 됨. 하나만 두면 그날은 바뀌지 않음

`items[]`의 주요 필드

- 공통: `time`, `name` 또는 `title`, `note`, `tip`(장소 설명), `cost`(숫자면 합계에 포함), `pid`(구글 장소 ID), `q`(지도 검색어)
- 평점: `g: [평점, 후기 수]`(구글), `tb: [평점, 후기 수]`(타베로그, 있을 때만 표시), `pro`, `con`(좋은 점, 아쉬운 점)
- `type`이 없으면 장소 카드
- `type: "move"`: 이동 카드. `route: {from, to, fromName, toName, mode}`
- `type: "run"`: 러닝 카드. `home`, `homeName`, `via[]`로 숙소에서 출발해 돌아오는 경로
- `type: "choice"`: 선택지. `options[]`, `multi`(여러 곳 체크 여부). 옵션의 `rec`는 "추천" 표시
- `type: "sleep"`: 취침 카드. `time`만 있으면 되고, 다음 날 첫 일정까지 남은 시간은 화면에서 계산

### weather.json

- `updatedAt`: 갱신 시각
- `data`: `{지점 키: {날짜: {code, max, min, pop, rain, wind, uv, sunrise, sunset, hours}}}`
  - `hours`는 시간별 `[시, 기온, 체감, 강수확률, 강수량, 날씨코드, 풍속, 습도]`
- `plan`: 날짜별로 정해진 일정 키
- `rain`: 날짜별 비 판정

### i18n.json

- `{en: {한국어: 영어}, ja: {한국어: 일본어}}`
- plan.json의 모든 문자열(trip 포함)을 이 사전으로 바꿔 표시
- 장소 ID, 지도 검색어, 시간대처럼 그대로 넘겨야 하는 값(`pid`, `q`, `home`, `from`, `to`, `timezone`)은 번역하지 않음
- 번역이 없는 문장은 한국어로 표시. 파일이 없으면 일정 내용은 모두 한국어로 표시
- 지원 언어는 한국어, 영어, 일본어 3개 (index.html의 화면 문구 사전)

### 일정 데이터 만들기와 번역

- 현재 plan.json은 `data/saved/`의 구글 지도 저장 목록을 바탕으로 저장소 밖의 빌드 스크립트로 만들었고, 저장소에는 원본 목록과 결과 파일만 있음. 위 구조만 맞으면 직접 작성하거나 다른 스크립트로 만들어도 됨
- 같은 카드는 `items`에 한 번만 두고 `days`에서 번호로 참조
- 번역 추가: plan.json에서 한글이 들어간 문자열 중 i18n.json의 `en`이나 `ja`에 없는 것을 찾아 추가. 번역하지 않는 키의 값은 제외

## 화면 기능

### 일정
- 앱을 열면 오늘 날짜 탭이 열림 (`trip.timezone` 기준). 여행 기간이 아니면 첫날 탭
- 상단에 여행 제목과 기간, 항공편, 날짜 탭
- 날짜 요약: 제목, 핵심 포인트, 교통비와 입장료 합계(식비 제외), 그날 노천탕, 날씨 카드
- 장소 카드: 시각, 비용, 장소 설명, 구글 평점과 후기 수, 타베로그 평점, 좋은 점과 아쉬운 점
- 이동 카드: 교통수단, 요금, 경로
- 러닝 카드: 숙소에서 출발해 경유지를 거쳐 돌아오는 순환 경로
- 장소가 있는 카드에는 "구글 지도" 링크와 "미리보기"(지도를 시트로 열기). 미리보기는 `config.js`에 키가 있을 때만 보임
- 안내 카드: 비 일정으로 바뀌면 "비 예보로 일정이 바뀌었습니다"와 빠진 장소, 날짜를 맞바꾸면 "날씨에 맞춰 날짜를 바꿨습니다", `towel`이 있으면 "수건 챙기기"
- 취침 카드: 하루 마지막에 밤하늘 색 카드로 취침 시각과 다음 날 첫 일정까지 남은 시간 (다음 날 날씨에 따른 일정 기준)
- 하단에 "저장 장소 더보기"(묶음별 장소 수 표시)와 안내 문구

### 현재 일정과 지난 일정
- 오늘 탭을 열면 지금 시각의 일정을 강조하고, 날짜 바 아래로 0.45초 안에 부드럽게 스크롤. 현재 일정 표시는 1분마다 갱신
- 이미 지난 일정은 "시각, 제목, 완료" 한 줄로 접히고, 왼쪽 초록 진행 선이 지금 일정까지 채워짐
- 지난 날짜는 일정 전체가 완료로 접혀 있음
- 접힌 줄에는 ⌄, 펼친 카드에는 "접기 ⌃"가 보이고 애니메이션으로 열고 닫힘
- 현재 일정이 화면에서 벗어나거나 다른 날짜를 보고 있으면 하단 캡슐이 나타남. 지금 일정, 다음 일정과 시각(없으면 "오늘 마지막 일정"), "이동" 버튼

### 선택지 (식사, 간식, 쇼핑)
- 하나 고르기와 여러 곳 체크 두 종류. 선택은 기기에 저장하고 언어를 바꿔도 유지
- 고르지 않은 선택지는 이름 한 줄로 접혀 있고 ⌄로 펼쳐 봄. 고른 곳만 펼쳐짐
- 펼칠 내용이 없는 선택지(생략 등)는 꺾쇠 없음

### 날씨
- 날짜별 날씨 카드: 날씨 상태, 기온(당일은 지금 기온과 체감, 다른 날은 낮 최고 기온), 최고, 최저, 최대 풍속, 평균 습도, 강수 확률, 자외선(낮음, 보통, 높음, 매우 높음, 위험), 갱신 시각
- 비 판정 기준 이상인 강수 확률은 파란색 표시
- 해, 달, 구름, 빗방울을 조합한 색 있는 날씨 아이콘. 당일 카드는 지금 시각이 일출 전이나 일몰 후면 밤 배경
- 움직이는 아이콘은 날짜별 날씨 카드의 큰 아이콘(해 회전, 구름 흔들림, 빗방울, 번개, 달 흔들림)과 취침 카드(달, z z Z)만. 인터랙션 효과를 끄거나 기기에서 동작 줄이기를 켜면 멈춤
- 카드를 누르면 시간별 시트: 날씨, 바람, 습도 탭과 가로 스크롤 그래프, 강수량, 일출, 일몰
- 예보 범위 밖 날짜는 "이 날짜 예보가 아직 없음"
- 갱신 시각은 보는 기기의 시간대로 표시. 그 밖의 시각은 `trip.timezone` 기준

### 조작과 화면
- 좌우로 밀어 날짜 이동 (옆 날짜 화면이 미리 채워진 채로 따라옴)
- 화면 맨 위에서 당겨서 새로고침 (iOS 스타일 12개 눈금이 당긴 만큼 채워짐)
- 시트(지도, 날씨, 설정 등)는 아래로 끌어내려 닫기. 안쪽 내용이 스크롤된 상태면 스크롤이 먼저
- 처음 열 때 모든 영역에 스켈레톤 표시
- 인터넷이 끊기면 상단에 오프라인 안내
- 설정: 언어, 인터랙션 효과(화면 전환, 등장 효과) 켜기/끄기, 다시 불러오기(홈 화면 앱용, 받아 둔 새 버전도 이때 반영)
- 라이트, 다크 모드 자동
- 언어를 바꾸면 그 자리에서 다시 그림 (스크롤 위치 유지). 지도 미리보기 언어, 금액 단위, 시간 표기(오전, 오후), 문장 부호도 언어에 맞춤

## 날씨와 일정 자동 조정

### 비 판정과 맞바꿈
- 날씨는 GitHub Actions가 `locations`의 지점마다 Open-Meteo 예보를 받아 `weather.json` 하나로 저장. 모든 접속자가 같은 파일을 읽음
- 그날 일정의 `weather` 지점 최대 강수 확률이 `rainThreshold` 이상이면 비 오는 날로 보고 `rain` 일정을 보여 줌
- 맞바꿈 규칙 (`trip.swap`)
  - `weights`에 있는 일정 날에 비가 오면 `base` 일정 날짜와 맞바꿈
  - 두 날짜 모두 서로의 일정을 `plans`에 갖고 있을 때만 맞바꿀 수 있음
  - 날짜마다 "가중치와 비 여부(비면 1, 아니면 0)를 곱한 값"을 더하고, 원래 일정에서 바뀐 날짜마다 0.5를 더해 합이 가장 작은 배치를 고름. 0.5는 불필요한 맞바꿈을 막는 값
  - 여러 날에 비가 오면 가중치가 큰 일정이 맑은 날을 가져감
- 오늘과 지난 날짜는 그 시점의 일정과 비 판정으로 고정해 여행 중 갑자기 바뀌지 않음. 고정된 일정이 나중에 `plans`에서 빠졌으면 그날 기본 일정으로 봄
- 내일 이후 일정이 날씨 때문에 바뀌면 안내 시트를 띄움. 같은 변경은 한 번만 보여 줌

### 갱신 주기
- main에 올릴 때마다 날씨 갱신 실행 (weather.json만 바뀐 커밋은 제외)
- 갱신이 끝나면 1시간 뒤 다음 실행을 스스로 요청 (GitHub 예약 실행이 자주 건너뛰어서 보완). 대기는 항상 하나만 남음
- 여행 마지막 날(`days`의 마지막 날짜, `trip.timezone` 기준)이 지나면 스스로 요청을 멈춤
- 예약 실행(매시 17분)도 백업으로 유지
- 날씨 작업이 올린 커밋은 다시 작업을 부르지 않아 반복되지 않음

## 오프라인과 업데이트

- 서비스 워커가 화면과 데이터(index.html, config.js, plan.json, i18n.json, manifest, 아이콘, weather.json)를 보관해 인터넷 없이도 열림
- 캐시는 두 개: `trip-active`(지금 보는 버전), `trip-staged`(받아 둔 새 버전). 화면을 새로 열 때 받아 둔 새 버전을 한꺼번에 옮겨 반영
- 날씨는 열 때마다 새로 받음 (GitHub API 우선, 실패하면 저장소 원본 주소). 2초 안에 못 받으면 보관본 사용
- 새 버전 확인 시점: 앱을 열고 3초 뒤, 인터넷이 다시 연결될 때, 화면으로 돌아올 때, 열어 둔 동안 15분마다. 다른 시트가 열려 있으면 5초 뒤 다시 확인
- 화면 코드, 일정, 번역 파일이 바뀌었거나 날씨 때문에 일정이 바뀌면 "새 일정이 있습니다" 시트로 새로고침할지 물음
- 날씨 숫자만 바뀐 경우는 묻지 않고 다음에 열 때 반영
- "나중에"를 누르면 앱을 연 동안 같은 변경은 다시 묻지 않음. 앱을 완전히 종료했다가 다시 열면 받아 둔 새 버전이 반영됨

## 홈 화면 앱

- 홈 화면에 추가하면 앱처럼 전체 화면으로 실행 (iOS 대응)
- PNG 아이콘(180, 192, 512, maskable), 노치 영역 대응, 확대와 길게 누르기 방지, 스크롤 튕김 방지
- 링크 공유용 제목, 설명, 미리보기 이미지(Open Graph) 설정

## 새 여행에 쓰는 법

1. `data/plan.json`을 새로 작성. 필수 키는 `trip`, `locations`, `rainThreshold`, `days`, `items`. 항공편, 저장 장소, 온천이 없으면 해당 키를 빼면 됨
2. `data/i18n.json`에 새 문장의 영어, 일본어 번역 추가
3. 아래 파일은 공유 미리보기와 홈 화면이 스크립트 없이 읽는 값이라 직접 수정
   - `index.html`의 `<title>`, `description`, `og:*`, `twitter:*`, `apple-mobile-web-app-title`
   - `manifest.webmanifest`의 `name`, `short_name`, `description`
   - `share.png`, `icon-*.png`, `icon.svg`
4. `data/weather.json`은 지우고 올리면 날씨 작업이 새로 만듦
5. 저장소 이름이나 계정을 옮기면 `index.html`과 `sw.js`의 날씨 주소(`WEATHER_URL`, `WEATHER_API`)를 수정하고, Google Cloud에서 API 키 사용 도메인을 바꿈

## 일정 작성 조건

여행자 기준 조건이라 지역과 상관없이 적용합니다.

- 매일 아침 러닝, 최대 5km
- 술 마신 뒤 자전거 타지 않기, 택시 안 타기, 가성비 위주 동선
- 장어, 아나고 요리는 제외
- 저녁 순서: 온천, 1차는 밖에서(도보), 2차는 늦게까지 하는 술집이나 편의점, 또는 생략. 마트 장보기는 하지 않음
- 취침은 2차 시작 1시간 30분 뒤
- 2차 선택지도 식사 선택지와 같은 형식 (늦게까지 하는 술집 5곳 + 편의점 + 생략)
- 식사 선택지 형식
  - 식당 5곳(구글 후기 많은 순, 종류는 다양하게) + 근처 편의점 + 생략 = 7개
  - 식당 이름 뒤에 종류 표기 (예: 다이짱 (야키니쿠))
  - 편의점은 "편의점 (세븐일레븐 추천)" 형식에 매장명, 주소, 구글 평점
  - 좋은 점 5개, 아쉬운 점은 후기와 확인된 사실(거리, 마감 시각, 결제 방식)로 최대 5개

## 운영 원칙

- 일정 변경은 관련 정보(영업시간, 요금, 교통)를 조사해 조율안을 만들고, 확인을 받은 뒤 반영
- 화면 디자인 변경은 시안을 먼저 보여 주고 확인을 받은 뒤 반영
- 커밋과 푸시는 허락을 받은 뒤 진행
- 사용자가 정한 조건은 임의로 바꾸지 않음
- 확인되지 않은 정보는 "확인 필요"로 표시
- 후기와 정보는 접근할 수 있는 출처만 사용. 막힌 사이트를 크롤러 등으로 우회하지 않고, 블로그 내용은 쓰지 않음
- 외부 서비스는 날씨(Open-Meteo)와 구글 지도만 사용. 브라우저에 쓰기 권한 토큰을 두지 않음
